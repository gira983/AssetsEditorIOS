# AssetsTools.NET bridge

This directory is the boundary between the SwiftUI iOS application and the verified AssetsTools.NET implementation.

AssetsTools.NET is a .NET Standard 2.0 library. The Swift app cannot import a NuGet assembly directly. The production bridge must therefore be built outside the Swift target as a native iOS-compatible artifact and exposed through a small C ABI.

The bridge must use only verified upstream APIs:

- `AssetsManager.LoadAssetsFile(string path, bool loadDeps = false)`
- `AssetsManager.LoadBundleFile(string path, bool unpackIfPacked = true)`
- `AssetsManager.LoadAssetsFileFromBundle(BundleFileInstance bunInst, string name, bool loadDeps = false)`
- `AssetsManager.GetBaseField(AssetsFileInstance inst, AssetFileInfo info, AssetReadFlags readFlags = AssetReadFlags.None)`
- `AssetTypeValueField.WriteToByteArray(bool bigEndian = false)`
- `AssetFileInfo.SetNewData(byte[])`
- `AssetsFile.Write(AssetsFileWriter writer, long filePos = 0)`
- `AssetBundleDirectoryInfo.SetNewData(byte[])`
- `AssetBundleFile.Write(AssetsFileWriter writer)`

The bridge must not expose managed objects to Swift. It should return UTF-8 JSON metadata and raw bytes through explicit ownership/release functions. File paths must be copied into bridge-owned storage before returning. Every exported operation needs a matching release function and an error buffer accessor.

## Planned native boundary

```text
Swift / SwiftUI
    |
    | C ABI: uae_open, uae_list_objects, uae_read_object,
    |        uae_write_object, uae_list_bundle_entries, uae_close
    v
AssetsToolsBridge.xcframework
    |
    | .NET NativeAOT static or shared native library
    v
AssetsTools.NET 3.x
```

The current Swift implementation deliberately uses `UnavailableAssetToolsBridge`. This is a compile-safe seam, not a fake parser and not a claim that AssetsTools.NET has been linked.

## Build requirements for the bridge

- .NET 9 SDK with the iOS NativeAOT workload/toolchain available on the build runner.
- AssetsTools.NET pinned to an exact package version and committed lock metadata.
- An arm64 iOS device artifact and an arm64 iOS Simulator artifact. A simulator x64 slice is optional only if the supported Xcode simulator matrix requires it.
- A C header and module map generated by the bridge project.
- A CI job that builds the bridge before the Xcode job and fails if the expected headers/library are absent.

Do not add a NuGet reference to the Swift Xcode project. Do not write Swift calls to `AssetsManager`, `AssetTypeValueField`, or any other managed type.
